# Project instructions

This is a portfolio demonstration, not evidence of client delivery. Preserve that distinction.

- Keep examples synthetic. Do not commit secrets, customer data, runtime databases or virtual environments.
- Run `python -m unittest discover -s tests -v` after substantive changes.
- Record actual validation in VALIDATION.md; do not infer live API or deployment success from mock tests.
- Prefer small explicit functions. Keep backend validation independent of the user interface.
- Document behavior changes and limitations in README.md.
- Bind demos to 127.0.0.1. Do not publish unauthenticated write APIs to the internet.
